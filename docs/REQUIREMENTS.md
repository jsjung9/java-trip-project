# 요구사항과 수용 기준

## 사용자와 인증

| ID | 요구사항 | 수용 기준 |
| --- | --- | --- |
| AUTH-01 | 사용자는 회원가입과 로그인을 할 수 있다. | 신규 비밀번호는 BCrypt로 저장되고 비밀번호·salt·refresh token은 응답 JSON에 포함되지 않는다. |
| AUTH-02 | 기존 사용자는 비밀번호 변경 없이 로그인할 수 있다. | 과거 SHA-256+salt 값이 맞으면 같은 트랜잭션에서 BCrypt로 교체하고 salt를 제거한다. |
| AUTH-03 | 인증 상태를 안전하게 갱신한다. | access token은 Bearer 헤더, refresh token은 HttpOnly·SameSite 쿠키로 전달하며 갱신 때 회전한다. |
| AUTH-04 | 다른 사용자의 요청 값을 이용한 변경을 차단한다. | 서버가 JWT 로그인 ID를 DB의 `editor_id`로 변환해 소유권을 검사한다. |

## 테마

| ID | 요구사항 | 수용 기준 |
| --- | --- | --- |
| THEME-01 | 사용자는 테마를 만들고 태그를 지정할 수 있다. | 생성 키를 즉시 반환하고 태그 교체는 원자적으로 처리한다. |
| THEME-02 | 작성자만 테마를 수정·삭제할 수 있다. | 다른 계정의 요청은 403이며 DB 변경이 없다. |
| THEME-03 | 공개 검색에 비공개 테마가 나타나지 않는다. | 전체·인기·장소별 검색은 `visible=1`만 반환한다. 비공개 상세는 작성자만 본다. |
| THEME-04 | 좋아요 수가 관계 데이터와 일치한다. | 관계 행이 실제로 추가·삭제된 경우에만 테마와 작성자의 집계값을 같은 트랜잭션에서 변경한다. |
| THEME-05 | 중복 좋아요를 허용하지 않는다. | `(editor_id, theme_id)` 유일 제약과 멱등 서비스 로직을 함께 적용한다. |

## 장소와 평가

| ID | 요구사항 | 수용 기준 |
| --- | --- | --- |
| PLACE-01 | Kakao 검색 장소를 테마에 연결할 수 있다. | 장소와 테마 관계를 각각 멱등하게 저장한다. |
| PLACE-02 | 공개 테마의 기여 수를 제한한다. | 작성자는 테마당 10개, 다른 사용자는 1개를 넘길 수 없다. |
| PLACE-03 | Private 테마는 작성자만 편집한다. | 다른 사용자의 장소 추가·삭제 요청은 403이다. |
| PLACE-04 | 장소 관계 삭제 권한을 제한한다. | 테마 작성자 또는 해당 장소를 추가한 사용자만 삭제한다. |
| PLACE-05 | 평점의 중복 누적을 막는다. | 1~5 정수만 받고 사용자·장소별 한 행을 upsert한 뒤 합계와 건수를 재계산한다. |

## 품질과 운영

| ID | 요구사항 | 수용 기준 |
| --- | --- | --- |
| OPS-01 | 비밀값을 저장소에 두지 않는다. | DB, JWT, Kakao 설정은 환경변수 예시만 제공한다. |
| OPS-02 | 새 환경에서 동일하게 실행할 수 있다. | Flyway 스키마와 Docker Compose로 Web/API/MySQL을 구성한다. |
| OPS-03 | 회귀를 자동으로 확인한다. | push와 PR에서 백엔드 테스트, 프론트 린트·테스트·빌드·감사를 실행한다. |
| OPS-04 | 내부 예외를 사용자에게 노출하지 않는다. | 공통 예외 처리기가 안정된 메시지만 응답하고 상세 스택은 서버 로그에 남긴다. |
